Run **External QC** on: $ARGUMENTS

External QC follows the Final Review Gate and is the last stage before TFRL, so no error is tolerated. Only verifier.json changes are in scope; an agreed finding against the prompt, sources or golden rejects the task. The true and false positive verdicts handed to the user must be final: they must not change when the user asks "you sure you agree with all findings? any other false positive?". Run it as a multi-agent orchestration with repeated rounds of checks, never as a single pass.

1. Prepare the inputs in the scratchpad: unzip the task pack into its own new directory; save the pasted finding cards verbatim to a file, keeping each exact header ("Review <id> · finding <n> · …"); keep the attached "verifier (NN).json" and any Final Review or earlier corrected verifier file; note any tracker fields the user gave (trainer name, email, task ID, task link with version). Confirm the screen matches the files (task ID, version, card count); on a mismatch, stop and say so in the first line.
2. Run the workflow: `Workflow({ scriptPath: ".claude/workflows/omega-external-qc.js", args: { pack_dir, findings_file, verifier_file, prior_verifier_file, scratch_dir, tracker_fields, user_notes } })`. Invoking this command is the user's opt-in to that orchestration. It runs an inventory and verifier diff, two independent verdict sets, an attack on Agree and an attack on Disagree for every card followed by a judge who re-derives the deciding fact, repeated on any card that is close, split or moved, a set-consistency pass, an "are you sure?" challenge, then template H answers and a pre-send check.
3. If the Workflow tool is unavailable, run the same rounds yourself with the Agent tool and the `project-omega-finance-review` agent, following reference 10 §4: two reviewers who never see each other's verdicts; for every card, an attacker of the Agree case and an attacker of the Disagree case, then a judge; repeat on any card that is close, split or moved; then set consistency, the challenge, the writer and the pre-send check. Never settle a split by vote.

Every brief carries the test from reference 10 §3: Agree (true positive) only when the finding's own complaint, tested on its own example of a correct answer, holds in the current verifier file and needs a verifier change; Disagree (false positive) when it does not, including every grader or infrastructure fault, which gets "No change needed to verifier.json" and an escalation line. The category tag never decides. Look for a sound verifier-only cure before agreeing that a defect lives in the prompt, sources or golden, and say in the first sentence when agreeing rejects the task. TAKE or REJECT each remediation item; never adopt one that edits the prompt, sources or golden, labels the planted item, adds an unasked condition or is an escape clause.

Before relaying, re-check every Agree-driving figure and quote yourself and read any "WRITER DOUBT" line; if one holds, re-run that card's rounds rather than editing the verdict. Relay the answers inline in screen order under C1–C8 in SKILL.md, without stripping fixes, with one lead line listing any verdict the rounds changed. Give a corrected verifier.json only if the user asks. If challenged later, re-test against the same bar; a changed verdict states "changed because <new evidence>".
