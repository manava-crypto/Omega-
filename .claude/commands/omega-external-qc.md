Run **External QC** on: $ARGUMENTS

External QC follows the Final Review Gate and is the last stage before TFRL (reference 10; the platform's own steps are in reference 12). The true and false positive verdicts must be final: they must not change when the user asks "you sure you agree with all findings?". If anything is agreed, the author fixes the task and uploads it once per round.

1. Inputs: exactly two files, the task zip from the task's RL World page and QC's `…-dataos-with-runs.zip` (the DataOS run with the reviews inside). Never ask for anything else: no manifest, config, setup file, login or install. Copy both, unrenamed, into a new scratchpad folder and unzip a copy of the task beside them; save any pasted items verbatim, each with its exact header. Confirm the task and version match; on a mismatch, stop and say so in the first line.
2. Run the workflow: `Workflow({ scriptPath: ".claude/workflows/omega-external-qc.js", args: { pack_dir, task_zip, runs_zip, findings_file, work_dir, prior_verifier_file, prior_notes_file, scratch_dir, user_notes } })`, with `work_dir` a fix folder inside the scratchpad. Invoking this command is the user's opt-in to that orchestration. It runs the `verifier-fix-trainer` skill's `trainer_fix.py start` into `work_dir` (FINDINGS.md, RUNS.md, SWEEP.md) as part of a shared evidence ledger, two independent reviews, judges only where the reviewers differ or are unsure (four items per judge, a second on any overturn, change or fix outside verifier.json, a third on a split), one "you sure you agree with all findings?" pass, then verdict-locked template H answers and a pre-send check. It returns `answers`, `verifier_fixes`, `other_fixes`, `changes`, `unsettled` and `qc_problems`. While it runs, do nothing else: it notifies you when done, so never poll it or review in parallel. If it returns `stop`, report a mismatch or use the fallback; if `unsettled` is not empty, settle those items first.
3. If any verifier item is agreed, finish the fix with the `verifier-fix-trainer` skill (`skills/verifier-fix-trainer/SKILL.md`) in the same `work_dir`: write `edits.json` from `verifier_fixes` (plus the same-family siblings SWEEP.md shows, unless the instruction requires that placement or wording), run `trainer_fix.py apply`, then `trainer_fix.py finish`, which stops at WAITING FOR THE AUTHOR. Show the user the one list the skill requires: every check changed, added or removed, with what QC found, what it said and what it says now, the siblings QC did not name, what was left as it is, and anything that is the author's to fix. Ask once whether to build the upload file. Only after their OK, run `finish --confirmed "<their words>"` and give them `fix_<task>/fixed/<same zip name>` to upload with Upload Updated Task. Never build the file on silence.
4. For each item in `other_fixes`, give the author the file and the exact change, checked against the upload rules in reference 12; never edit those files.
5. If the Workflow tool is unavailable, run the same stages with the Agent tool: `trainer_fix.py start` and the ledger, two independent reviewers who never see each other's verdicts, batched judges on contested items with second and third judges as above, one challenge pass, the writer and the pre-send check. Never settle a split by vote.

Relay inline, in screen order, under C1–C8 in SKILL.md: the lead, one entry per item (Agree in one or two sentences, Disagree with its note), the fix plan, then the skill's list of changed checks and the question for the author's OK. Re-check yourself only the deciding fact of each Agree whose fix lies outside verifier.json. If challenged later, re-test against the same bar; a changed verdict states "changed because <new evidence>".
