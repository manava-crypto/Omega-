Run **External QC** on: $ARGUMENTS

External QC follows the Final Review Gate and is the last stage before TFRL (reference 10; the platform's own steps are in reference 12). The true and false positive verdicts must be final: they must not change when the user asks "you sure you agree with all findings?". If anything is agreed, the expert fixes the task and uploads it once per round.

1. Prepare the inputs: keep the fresh RL World download (Quality Checks → Export & Download → Download artifacts) unrenamed, with its `.external-qc-manifest.json`, and make an unzipped copy in a new scratchpad folder; save the pasted items verbatim to a file, each with its exact header ("Review <id> · finding <n> · …"); keep QC's `-external-qc-feedback.json` and runs zip, and any Final Review verifier file and notes. Confirm the screen matches the files (task ID, version, item count); on a mismatch, stop and say so in the first line.
2. Run the workflow: `Workflow({ scriptPath: ".claude/workflows/omega-external-qc.js", args: { pack_dir, findings_file, feedback_json, runs_zip, prior_verifier_file, prior_notes_file, scratch_dir, user_notes } })`. Invoking this command is the user's opt-in to that orchestration. Two agents build a shared evidence ledger (the named criteria, prompt clauses, source and golden facts, recomputed figures, and the run snapshot from the skill's `task_snapshot.py`); two independent reviews run from it; only items where the reviewers differ or are unsure go to judges, four per judge; a second judge confirms any overturn, any change and any Agree whose fix lies outside verifier.json, and a third settles a split; one "you sure you agree with all findings?" pass; then verdict-locked template H answers and a pre-send check. It returns `answers`, `verifier_fixes`, `other_fixes`, `changes`, `unsettled` and `qc_problems`. While it runs, do nothing else: it notifies you when done, so never poll it or start your own review in parallel. If it returns `stop`, report a mismatch in the first line or use the fallback; if `unsettled` is not empty, settle those items before relaying.
3. If any verifier item is agreed, run the `verifier-json-fix` skill in expert mode (`skills/verifier-json-fix/SKILL.md`, step 4 of "Start here"; `assets/START-PROMPT-EXPERT.md`) on the download, the feedback file and the runs zip, giving it the agreed change per item from `verifier_fixes`. It changes tests/verifier.json only, scopes the upload to feedback-named verifiers and ends `ROUND 1: READY` with `round1/trainer/<download name>_verifierfix_upload.zip`, one line per QC item and a next-round list. Ask the user before any install. If it reports `ROUND 1: NOT READY`, fix what it names and build the next round; never zip by hand.
4. For each item in `other_fixes`, give the expert the file and the exact change, checked against the upload rules in reference 12; never edit those files yourself unless the user asks.
5. If the Workflow tool is unavailable, run the same stages with the Agent tool: the ledger, two independent reviewers who never see each other's verdicts, batched judges on contested items with second and third judges as above, one challenge pass, the writer and the pre-send check. Never settle a split by vote.

Relay inline, in screen order, under C1–C8 in SKILL.md: the lead, one entry per item (Agree in one or two sentences, Disagree with its note), the fix plan, then the skill's upload file name, its one line per QC item (for where RL World asks what changed) and its next-round list. Re-check yourself only the deciding fact of each Agree whose fix lies outside verifier.json. If challenged later, re-test against the same bar; a changed verdict states "changed because <new evidence>".
