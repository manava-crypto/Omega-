Run **Final Review** on: $ARGUMENTS

Final Review is the most important gate. Rejecting Task Design, a source document, the prompt or the golden ends the task; a verifier REJECT sends that verifier back for repair and the task continues. Shipping a wrong task and terminating a correct one are both failures, so the answers handed to the user must be right the first time and must not change when the user asks "are you sure?". Run it as a multi-agent orchestration with repeated rounds of checks, never as a single pass; each verdict is confirmed by two consecutive judgments before it is written.

1. Prepare the inputs in the scratchpad: unzip the package into its own new directory; save the pasted Final Review screen verbatim to a file; save any prior review notes to a file. Confirm the upload matches the screen (task_id, revision, deliverable paths, verifier names); on a mismatch, stop and say so in the first line.
2. Run the workflow: `Workflow({ scriptPath: ".claude/workflows/omega-final-review.js", args: { pack_dir, screen_file, prior_notes_file, scratch_dir, user_notes } })`. Invoking this command is the user's opt-in to that orchestration. It runs an inventory, two independent full reviews plus an External QC-lens hunter, then prosecutor, defender and judge rounds on every contested field until each verdict is confirmed by two consecutive judgments (a final judge settles anything still moving after three rounds; a task-ending REJECT needs two concurring judges, with a third on a split), up to three "are you sure?" challenges, fix reconciliation, verdict-locked template F answers and an Auto QC pre-check rerun after every revision. It returns `answers`, `changes`, `unsettled` and `qc_problems`. If it returns `stop`, report a mismatch to the user in the first line, or use the fallback when the inventory or reviews failed. If `unsettled` is not empty, re-run those fields through the fallback rounds before relaying anything; if `qc_problems` is not empty, fix them without changing a verdict.
3. If the Workflow tool is unavailable, run the same rounds yourself with the Agent tool and the `project-omega-finance-review` agent: two independent reviewers who never see each other's verdicts; for every field where they split, either rejects, either marks a close call or the hunter raises a candidate, a prosecutor and a defender in parallel and then a judge who re-derives the deciding fact from the files; a second judge for any Task Design, source, prompt or golden REJECT; a second round on every field whose judge overturned a reviewer or marked a close call, and again on any verdict that moved, until two consecutive judgments agree; then the challenge pass, the writer and the Auto QC pre-check. Never settle a split by vote.

Every brief carries the bar: a verifier is rejected only when (a) its rubric misstates a governing term, (b) a realistic submission is mis-graded, shown on a supplied output or a fully described submission under an accepted reading (a PASS condition the prompt never asks for, or a single accepted reading where the prompt and sources allow another, meets this), or (c) where verifier and golden disagree, the verifier is the one that is wrong. The golden is rejected only when it truly fails a sound verifier or recomputes wrong from source; a non-verifier artifact only for a defect a correct solver cannot work around that the sources, the authority order and the prompt do not resolve. Everything else is an optional line: stale figures that change no result, hypothetical overlap or bundling, reasonable placement or format readings the prompt supports, extractor observability (NOT VERIFIABLE plus escalation), weight or difficulty labels, mechanical source slips and planned difficulty.

Before relaying, re-check yourself every REJECT's deciding fact and classification and every task-ending verdict (the workflow has already re-adjudicated any doubt its writer raised); if a check fails, re-run the adjudication on that field rather than editing the verdict. Relay the answers inline in screen order under C1–C8 in SKILL.md, without stripping fixes, with one lead line listing any verdict the rounds changed. If the user later challenges a verdict, re-test it against the same bar; a changed verdict states "changed because <new evidence>".
