# Final Review Brief (for orchestrated agents)

Read this instead of the full rulebook when you are one agent in the Final Review workflow. The evidence ledger the workflow built is your first source; open a task file only to confirm or extend a fact the ledger does not settle.

## Stakes

Rejecting Task Design, a source document, the prompt or the golden ends the task. A verifier REJECT sends that verifier back for repair and the task continues. Shipping a wrong task and terminating a correct one are both failures.

## Bar

- Task Design: judged on its own terms, never against verifier scope. APPROVE when the scenario is realistic, deliverables have clear purposes, sources are mapped, and planned anomalies are realised in the sources and carried into instruction.md.
- Source document or prompt: REJECT only for a defect a correct solver cannot work around that the sources, the authority order and the prompt do not resolve. Read the cover and notes sheets and the prompt's caveats first; planned difficulty is APPROVE.
- Verifier: REJECT only when (a) the rubric misstates a governing term; (b) a realistic submission is mis-graded, written as "A submission that … would FAIL/PASS because …" (a PASS condition the prompt never asks for, such as a literal figure, label, closed list, fixed placement or hard date, or a single accepted reading where the prompt and sources allow another, meets this); or (c) where verifier and golden disagree, the verifier is the one that is wrong.
- Golden: REJECT only when it truly fails a sound verifier or recomputes wrong from source. Grade it literally against every FAIL clause, labels and ordering wording included.
- Everything else is an optional line: stale figures that change no result, hypothetical overlap or bundling, placement or format readings the prompt supports, extractor observability (NOT VERIFIABLE plus escalation), weight or difficulty labels, mechanical source slips, planned difficulty.

## Probes worth running on a verifier

Corner sweep of every anchor and band across defensible conventions; one-owner check (one defect failing two verifiers); each/every means the full population; governing terms quoted with all their conditions; every embedded figure recomputed; the pass case tested against the governing standard; the golden graded against the text.

## Notes

Notes cite only what the gate shows (instruction, sources, verifier.json, golden), never a model output by name. A REJECT note: the defect in one plain sentence, evidence with a quoted locator, the counterexample, then "Fix:" with the exact change (quote the current text, give the replacement). An APPROVE is one sentence of evidence. Plain words, no tool or file-internal names, no cross-references.
